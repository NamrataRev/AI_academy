## 1. What is an API?

An **API (Application Programming Interface)** is a set of rules that lets two different software systems talk to each other. 
If Python is the "orchestrator," an API is the **doorway** through which Python asks another system (like Anthropic's servers) to do work.

### Request and Response
Every API interaction works on a fundamental cycle:
1. **The Request:** Your Python code sends a package of data through the API. This package contains your authentication (who you are) and the payload (what you want the system to do — your prompt).
2. **The Server works:** The remote system receives the request, processes it (e.g., the LLM generates text), and packages the result.
3. **The Response:** The remote system sends a package of data back to your Python code.

---

## 2. The Anthropic API

To call an LLM like Claude, you don't download the model to your laptop. Instead, you send API requests to Anthropic's servers. The Anthropic API requires a few specific ingredients in every request:

1. **Authentication (API Key):** A secret password (`sk-ant-api03...`) proving you have permission and an account to bill.
2. **Model:** Which specific version of the model you want to use (e.g., `claude-3-opus-20240229` for complex reasoning, or `claude-3-haiku-20240307` for speed).
3. **Messages Array:** A structured list of the conversation history. Instead of one long string of text, you send a list of dictionaries denoting who said what (`"role": "user"` or `"role": "assistant"`).
4. **System Prompt (Optional):** High-level instructions defining the model's persona, boundaries, and overall rules for the interaction.

---

## 3. Making the First API Call

To interact with the Anthropic API effortlessly in Python, we use the official Anthropic Python library. 

### Step 1: Install the library (in Google Colab)
Before you can import the library, you must install it. In Colab, you use the `!` symbol to run a terminal command:
```bash
!pip install anthropic
```

### Step 2: Write the call
```python
import anthropic

# 1. Initialize the client with your secret API key
client = anthropic.Anthropic(
    api_key="YOUR_SECRET_API_KEY_HERE"
)

# 2. Make the API request
response = client.messages.create(
    model="claude-3-haiku-20240307",
    max_tokens=1000,
    system="You are a strict code reviewer. Return only actionable feedback.",
    messages=[
        {
            "role": "user",
            "content": "Review this python code: print(Hello World)"
        }
    ]
)
```

---

## 4. Parsing the JSON Response

When the Anthropic API replies, it does not just hand back a raw string of text. It hands back a structured object (often represented conceptually as JSON) containing metadata: how many tokens were used, what model processed it, and the actual text message.

If you just print the `response` object, you'll see a complex structure. You need to **extract the text you need**.

```python
# The response object contains a list of content blocks. 
# We usually want the text of the first block.

raw_text = response.content[0].text
print(raw_text)
```

## 5. Handling API Errors

Network calls fail. The internet drops, the API key might be expired, or you might send a request that is too large. If you don't handle these errors gracefully, your entire orchestration script crashes.

We use the `try / except` pattern specifically looking for Anthropic's error types:

```python
import anthropic

client = anthropic.Anthropic(api_key="YOUR_KEY")

try:
    response = client.messages.create(
        model="claude-3-haiku-20240307",
        max_tokens=1000,
        messages=[{"role": "user", "content": "Hello!"}]
    )
    print(response.content[0].text)

except anthropic.AuthenticationError:
    print("Error: Your API key is invalid or expired.")
except anthropic.APIConnectionError:
    print("Error: Could not connect to Anthropic servers. Check your internet.")
except anthropic.RateLimitError:
    print("Error: You are making requests too quickly. Please slow down.")
except Exception as e:
    print(f"An unexpected error occurred: {e}")
```

---

## 6. Every API Call is a Design Decision

In AI-native engineering, calling an API is not free. Every time you type `client.messages.create(...)`, you are making a deliberate design decision balancing three constraints:

1. **Cost:** You are billed per token (both input and output). Sending a massive 50-page document in the prompt is expensive. Is the context strictly necessary?
2. **Latency (Speed):** The more text the model has to read, and the more complex the model is (Opus vs Haiku), the longer the user waits. If you are building a real-time chatbot, using the smartest, slowest model might ruin the user experience. 
3. **Reliability:** Complex models follow instructions better but fail if overloaded. Fast models respond instantly but might ignore subtle system prompts. 

Professional engineers do not default to the biggest model. They orchestrate the right model for the right job — perhaps using Haiku to quickly classify user intent, and Opus to write the final complex report.
