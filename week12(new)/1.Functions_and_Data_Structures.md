## 1. Functions — Named, Reusable Blocks of Logic

A **function** is a named, reusable block of code that performs one specific task. You write it once, and then you can **call** it (run it) as many times as you need, from anywhere in your program, without retyping the logic inside it. 

### Why do we need functions?
Without functions, every program would be one long, ever-growing script. Any task you needed twice would have to be retyped, and any change to that task would mean hunting down and fixing every copy by hand. 
In AI-native engineering, functions act as the building blocks for interacting with models and parsing outputs safely.

### Defining and Calling a Function
You create a function using the `def` keyword, a name, a pair of parentheses, and a colon. The indented block underneath is the function's **body**.

```python
def print_welcome_banner():
    """Prints the application's welcome banner."""
    print("======================================")
    print("      AI-NATIVE ENGINEERING APP")
    print("======================================")
```
Defining a function does **not** run it. You run the body by **calling** the function:
```python
print_welcome_banner()  # This executes the print statements inside the function
```

## 2. Parameters and Return Values

Functions become powerful when you can send data **in** and get data **out**.

### Parameters (What Goes In)
A **parameter** is a placeholder variable defined in the function's declaration. When you call the function, you pass an **argument** (the actual value) into that parameter.

```python
def greet_user(name):
    # 'name' is the parameter
    print(f"Hello, {name}! Welcome to the system.")

greet_user("Priya")  # "Priya" is the argument
```

### Return Values (What Comes Out)
A function that only `print()`s data has done something visible on the screen, but it has handed nothing back to whoever called it. The `return` statement ends the function immediately and produces a **return value** — a result the caller can store in a variable or use in further calculations.

```python
def calculate_tax(amount):
    tax = amount * 0.18
    return tax  # Hands the value back to the caller

# The returned value can be stored in a variable
order_tax = calculate_tax(500)
print(f"Tax to pay: {order_tax}")
```
**Crucial Distinction:** `print()` is for humans to read on a screen. `return` is for the program to use the data in the next step.

## 3. One Function = One Job (The Testable Unit Principle)

In professional software engineering, every function should do exactly **one job**, and its name should accurately describe that job. This is the **Testable Unit Principle**.

### The Problem with "Do Everything" Functions
Imagine a function called `process_order(cart)`. Inside this one function, the code calculates the total, applies a discount, validates the user's credit card, updates the database, and sends a confirmation email. 
If the total calculation is wrong, you have to run the *entire* checkout process (including sending emails and charging cards) just to test a math fix.

### The Solution: Isolation
Break it down into isolated, single-purpose functions:
1. `calculate_total(cart)` -> returns a number.
2. `apply_discount(total, code)` -> returns a discounted number.
3. `charge_card(amount, card_info)` -> returns a success/failure boolean.

By isolating jobs, you can write an automated test that passes `[100, 50]` to `calculate_total()` and verifies it returns `150`, without accidentally charging a real credit card.

## 4. Lists — Storing and Iterating Over Multiple Values

A **List** is Python's fundamental data structure for storing an ordered collection of items. Lists are created using square brackets `[]`.

### Creating and Accessing Lists
```python
# A list of strings
technologies = ["Python", "SQL", "Colab", "Git"]

# Accessing items by index (0-indexed)
print(technologies[0])  # Output: Python
print(technologies[-1]) # Output: Git (negative index gets the last item)
```

### Iterating over Lists
Lists are designed to be walked through, item by item, using a `for` loop:
```python
cart_items = [15.99, 20.50, 4.99]
total = 0

for item_price in cart_items:
    total += item_price

print(f"Total Cart Value: {total}")
```

### Modifying Lists
Lists are **mutable** (changeable). You can add, remove, or modify elements after the list is created:
```python
tasks = ["Draft spec", "Review logic"]
tasks.append("Write tests")       # Adds to the end of the list
tasks[1] = "Review AI logic"      # Modifies the second item
```

## 5. Dictionaries — Key-Value Pairs for Structured Data

While a list is an ordered sequence, a **Dictionary** (`dict`) is a collection of **key-value pairs**. It allows you to look up a value by its unique name (the key) rather than its numerical position. Dictionaries use curly braces `{}`.

### Creating and Accessing Dictionaries
```python
# A dictionary representing a single user
user_profile = {
    "username": "arjun_dev",
    "role": "Admin",
    "is_active": True,
    "login_count": 42
}

# Accessing a value by its key
print(user_profile["username"])  # Output: arjun_dev
```

### Why use Dictionaries over Lists?
If you stored user data in a list `["arjun_dev", "Admin", True, 42]`, you would have to remember that index `1` is the role. In a dictionary, the data is explicitly labelled, making it perfect for representing complex, structured objects (like a row in a database, or a JSON response from an AI API).

### Modifying Dictionaries
You can easily add new keys or update existing ones:
```python
# Updating an existing key
user_profile["login_count"] = 43

# Adding a brand new key-value pair
user_profile["department"] = "AI Engineering"
```

### Iterating over Dictionaries
You can loop through the keys, the values, or both simultaneously using `.items()`:
```python
for key, value in user_profile.items():
    print(f"{key}: {value}")
```
