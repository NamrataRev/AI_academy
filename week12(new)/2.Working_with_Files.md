## 1. Working with Files

In real-world applications, data rarely lives entirely in memory. It is stored on disk in files (like `.txt`, `.csv`, or `.json`). To build an AI-native application, you must be able to read specifications or datasets from files and write the AI's generated outputs back to files.

Python handles files in a simple three-step process: **Open -> Act -> Close**.

### Reading from a File

To read a file, you use the built-in `open()` function in read mode (`"r"`). 

```python
# 1. Open the file in read mode
file = open("prompt_instructions.txt", "r")

# 2. Act: Read all lines into a list
lines = file.readlines()
for line in lines:
    print(line.strip())  # .strip() removes the invisible newline characters

# 3. Close the file to free up system resources
file.close()
```

### Writing to a File

To write to a file, you open it in write mode (`"w"`). 
**Warning:** Opening a file in `"w"` mode will instantly erase anything currently in the file. If you want to add to the end of an existing file, use append mode (`"a"`).

```python
# 1. Open the file in write mode
file = open("ai_output.txt", "w")

# 2. Act: Write data to the file
file.write("This is the generated response from the model.\n")
file.write("It is saved permanently to the disk.")

# 3. Close the file
file.close()
```

### The Best Practice: The `with` Statement
Manually calling `file.close()` is dangerous because if an error occurs during the "Act" step, the program crashes before reaching the `close()` line, leaving the file locked or corrupted. 

Python provides the `with` statement (a context manager) that automatically closes the file for you the moment the block ends, even if an error occurs. **Always use this in professional code:**

```python
with open("ai_output.txt", "r") as file:
    content = file.read()
    print(content)
# No file.close() needed; Python closes it automatically here.
```

## 2. Handling Errors Gracefully (`try` / `except`)

When your code interacts with the outside world (like opening a file, calling an AI API, or parsing user input), things will inevitably go wrong. Files might be missing, the network might drop, or the user might type text when you expected a number.

If you don't anticipate these errors, your program will crash abruptly with a traceback. 

### The `try` / `except` Block
You can catch and handle errors using a `try` / `except` block. You put the risky code inside the `try` block. If it fails, Python immediately jumps to the `except` block instead of crashing.

```python
try:
    # Risky code: The file might not exist!
    with open("missing_config.json", "r") as config_file:
        data = config_file.read()
        print("Config loaded.")
        
except FileNotFoundError:
    # Graceful recovery
    print("Warning: Config file not found. Falling back to default settings.")
    data = "{}" # Apply defaults
```

### Catching Multiple Types of Errors
Different things can go wrong in the same block of code. You can stack `except` blocks to handle different failures appropriately.

```python
def process_user_age(input_string):
    try:
        age = int(input_string)
        result = 100 / age
        print(f"Age processed: {result}")
        
    except ValueError:
        print("Error: Please provide a valid number, not text.")
    except ZeroDivisionError:
        print("Error: Age cannot be zero.")
    except Exception as e:
        # A catch-all for any other unexpected error
        print(f"An unexpected error occurred: {e}")

process_user_age("twenty")  # Triggers ValueError
process_user_age("0")       # Triggers ZeroDivisionError
```

### Why is this critical for AI Engineering?
When you send a prompt to an AI model via an API, you are making a network request. That request might time out, or the API might be overloaded and return a `503 Service Unavailable` error. 

Without `try` / `except`, your entire orchestration script will crash the moment the API hiccups. With it, you can catch the connection error, wait 5 seconds, and automatically retry the request — building a resilient, professional system.
