# Professional Coding Discipline

As you begin to integrate AI into your coding workflow, professional discipline becomes more critical than ever. AI models are powerful assistants, but you are the engineer accountable for the system's safety and correctness.

## 1. Spec-First Discipline
**Spec-first discipline** means writing a clear, plain-English specification *before* you write any code or ask an AI to generate code for you.

A robust specification clearly defines:
1. **Inputs:** What data is the function receiving? (e.g., "A positive integer representing age").
2. **Expected Output:** What exactly should happen if the inputs are valid?
3. **Failure Conditions:** What should happen if the inputs are invalid or unexpected?

Without a spec, you have no objective measure of whether the AI's generated code is actually "correct" or just merely "executable."

## 2. The Golden Rule
**The Golden Rule:** *Never run code you cannot explain line by line.*

When an AI generates a block of Python for you, do not blindly copy, paste, and execute it. Code executes with real consequences—it can delete files, corrupt databases, or expose sensitive data. 
- Read every line.
- If you don't understand a line, ask the AI to explain it.
- Verify that the logic perfectly matches your initial specification.

## 3. Edge Cases
An **edge case** is a test that evaluates what happens at the extreme boundaries of expected input. Testing the "happy path" (normal inputs) is easy, but bugs and AI hallucinations usually hide at the edges.

**Always test your code against:**
- **Zero or negative numbers** (e.g., calculating a discount on a $0 cart).
- **The exact boundary value** (e.g., if a rule applies to ages "18 and over", test exactly `18`).
- **Empty lists or missing data** (e.g., running a loop on an empty user list).
- **Unexpected data types** (e.g., passing the string `"ten"` instead of the integer `10`).

By identifying and testing these boundary conditions, you ensure your orchestration layer is resilient and safe for production use.
