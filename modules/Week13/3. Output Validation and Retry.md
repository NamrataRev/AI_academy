## Overview

Even with the perfect system prompt, flawless role assignment, and robust constraints, Large Language Models are fundamentally probabilistic. This module explains why relying blindly on AI output is dangerous and teaches how to build resilient applications using validation and retry logic.

---

## The Reality of Probabilistic Models

Large Language Models generate text by predicting the most likely next word. 

Because of this, an LLM will occasionally ignore a constraint, hallucinate a new JSON key, or include unwanted conversational filler (e.g., *"Here is the JSON you requested:"*). 

If your Python application blindly trusts the AI's output, it will eventually crash. To build resilient AI applications, you must implement **Output Validation** and **Retry Logic**.

**Daily-life example:** Imagine ordering a burger with no pickles at a drive-thru. Before you drive away and take a bite (trusting the output), you open the box to check (Validation). If you see pickles, you don't throw the burger away and crash your car; you hand it back to the window and say, "I asked for no pickles, please fix this" (Retry Logic).

**Beginner-friendly way to remember:** Trust, but verify. And if it's wrong, ask again.

## 1. Output Validation

Output validation is the process of inspecting the AI's response in Python *before* you allow your application to use it. 

Validation can happen at multiple levels:
- **Syntax Level:** Is the output valid JSON? Can `json.loads()` parse it?
- **Schema Level:** Does the parsed dictionary contain the specific keys you need? (e.g., `if "risk_score" not in data:`)
- **Type Level:** Are the values the correct data type? (e.g., is the risk score an integer between 1 and 100?)
- **Business Logic Level:** Does the output make sense in the real world?

### Example: Validating JSON Schema
Here is how you validate that the AI not only returned JSON, but returned the *correct* JSON.

```python
import json

def validate_response(raw_ai_text):
    # Level 1: Syntax Validation
    try:
        data = json.loads(raw_ai_text)
    except json.JSONDecodeError:
        return False, "Output was not valid JSON."
        
    # Level 2: Schema Validation
    if "user_name" not in data or "age" not in data:
        return False, "Missing required keys: 'user_name' or 'age'."
        
    # Level 3: Type Validation
    if not isinstance(data["age"], int):
        return False, "'age' must be an integer."
        
    return True, data
```

## 2. Retry Logic

What happens when validation fails? If an end-user is waiting for a response, simply crashing or returning "Error" provides a terrible user experience. 

Instead, your code should automatically **retry** the API call. Because LLMs are non-deterministic (especially if the `temperature` parameter is greater than 0), calling the API a second time with the exact same prompt will often yield a correct, compliant response.

### The Self-Correction Pattern
The most advanced form of retry logic involves taking the error message generated during validation and feeding it *back* to the LLM. You tell the AI: *"You failed. Here is why. Try again."*

### Implementing a Retry Loop in Python

Here is a robust pattern for calling an LLM, validating its output, and automatically retrying if it fails.

```python
import anthropic
import json

def extract_user_info_with_retry(user_text, api_key, max_retries=3):
    client = anthropic.Anthropic(api_key=api_key)
    
    system_prompt = """
    Extract the user's name and age from the text.
    You must output ONLY valid JSON matching this schema:
    {"user_name": "string", "age": integer}
    """
    
    # Store the conversation history so we can append errors if needed
    messages = [{"role": "user", "content": user_text}]
    
    for attempt in range(max_retries):
        try:
            # 1. Make the API Call
            response = client.messages.create(
                model="claude-3-haiku-20240307",
                max_tokens=150,
                system=system_prompt,
                messages=messages
            )
            
            raw_output = response.content[0].text
            
            # 2. Validate the Output
            try:
                data = json.loads(raw_output)
                
                # Check for required keys
                if "user_name" not in data or "age" not in data:
                    raise ValueError("Missing required keys.")
                
                # If we reach here, the data is perfect! Return it.
                return data
                
            except (json.JSONDecodeError, ValueError) as e:
                # 3. Validation Failed: Prepare the Retry
                print(f"Attempt {attempt + 1} failed: {str(e)}")
                
                if attempt < max_retries - 1:
                    # Append the AI's bad response and our error message to the history
                    messages.append({"role": "assistant", "content": raw_output})
                    messages.append({
                        "role": "user", 
                        "content": f"Your previous response failed validation with this error: {str(e)}. Please correct it and output strictly valid JSON."
                    })
                else:
                    print("Max retries reached. Giving up.")
                    return None
                    
        except Exception as api_error:
            # Catch network or authentication errors
            print(f"API Error: {api_error}")
            return None

# Test it
# result = extract_user_info_with_retry("My name is Dave and I am forty years old.", "your-key")
# print(result)
```

### Why this works:
1. **`max_retries`**: Prevents the `for` loop from running infinitely if the prompt is completely broken. Usually, 3 retries is the industry standard.
2. **Contextual Awareness**: By appending the failed attempt and the exact error message to the `messages` array, the AI understands *why* it failed and adjusts its behavior on the next loop.
3. **Graceful Degradation**: If it still fails after 3 attempts, the function returns `None` instead of crashing the entire application, allowing the developer to handle the failure gracefully.

## Key Takeaway

Because LLMs are probabilistic, they will occasionally fail to adhere to your output constraints. Robust AI applications never blindly trust model output; they validate the response at the syntax and schema levels, and use programmatic retry loops (often feeding the error message back to the model) to self-correct failures without crashing the application.
