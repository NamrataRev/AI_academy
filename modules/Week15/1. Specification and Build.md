## 1. Writing a Formal Problem Statement and 1-Page Specification

Before writing a single line of code, professional engineers define exactly what they are building and why. Skipping this step leads to "scope creep" and messy code.

### The Problem Statement
A good problem statement answers three questions:
1. What is the current manual or broken process?
2. Why is it a problem (time, money, accuracy)?
3. How will AI solve it?

**Example:**
> *"Currently, our customer support team spends 15 hours a week manually reading unstructured feedback emails and categorizing them into 'Bug', 'Feature Request', or 'Billing Issue'. This is slow and error-prone. We will build an AI service to automatically read these emails and output a structured JSON categorization, reducing manual triage time by 90%."*

### The 1-Page Specification
Your 1-page spec serves as the blueprint for your application. It should include:
- **Input:** What data is coming in? (e.g., Raw text from an email).
- **Output:** What exactly must the system return? (e.g., A JSON object with `category` and `sentiment`).
- **Pattern:** Are we using a Direct Call, Chained Calls, RAG, or an Agent?
- **Constraints:** What are the hard boundaries? (e.g., "The AI must not attempt to reply to the email").

## 2. Building the Python Orchestration Layer

The LLM is just the engine; Python is the chassis that holds it together. The orchestration layer is responsible for taking the input, constructing the prompt, handling the network request, and catching any errors.

A robust orchestration layer should include:
- **Environment variables** to securely load your API key (never hardcoded!).
- A **`try/except` block** to handle network timeouts or authentication failures.
- **Retry logic** in case the API rate limits your request.

```python
import os
import anthropic
import json

def process_feedback(email_text):
    # Load the key securely
    api_key = os.getenv("ANTHROPIC_API_KEY")
    client = anthropic.Anthropic(api_key=api_key)
    
    # ... prompt definition goes here ...
    
    # Basic orchestration with a try/except block
    try:
        response = client.messages.create(
            model="claude-3-haiku-20240307",
            max_tokens=150,
            system=system_prompt,
            messages=[{"role": "user", "content": email_text}]
        )
        return response.content[0].text
    except Exception as e:
        print(f"API Error: {e}")
        return None
```

## 3. Writing a 5-Role Context-Engineered System Prompt

With the Python shell in place, you must write the system prompt that will guide the AI. Instead of a basic instruction, we use the **5-Role Context Framework** (learned in Week 13) to guarantee performance.

```python
system_prompt = """
<authority>
You are an expert Data Triage Bot for a software company. You are highly analytical and objective.
</authority>

<metadata>
Valid Categories: "Bug", "Feature Request", "Billing Issue".
</metadata>

<rubric>
You will be evaluated on your ability to strictly adhere to the JSON schema and accurately map the email to one of the three Valid Categories.
</rubric>

<constraints>
1. Output ONLY valid JSON.
2. Do not include markdown formatting or conversational text.
3. If the email does not fit a category, use "Unknown".
</constraints>

<exemplars>
Example Input: "I tried logging in but the screen goes white."
Example Output: {"category": "Bug", "confidence": 0.95}
</exemplars>
"""
```

## 4. Producing Structured JSON Output and Validating It

The final step of the build is taking the raw text output from the AI and converting it back into structured Python data so the rest of your application can use it. 

If you request JSON, you must validate it before proceeding.

