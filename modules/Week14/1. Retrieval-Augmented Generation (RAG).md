# Topic 1: Retrieval-Augmented Generation (RAG)

---

## What is RAG?

Large Language Models (LLMs) are incredibly smart, but they suffer from a major limitation: they only know what they were trained on, up to a specific cutoff date. If you ask an LLM a question about your company's private HR policies or today's breaking news, it will either refuse to answer or, worse, hallucinate a plausible-sounding but completely incorrect response.

**Retrieval-Augmented Generation (RAG)** is the industry-standard architecture designed to solve this problem. 

Instead of relying on the LLM's internal "memory" (its weights), RAG gives the LLM an open-book test. It first *retrieves* relevant documents from a database and then *augments* the prompt by injecting those documents as context before asking the model to *generate* an answer.

---

## Why RAG Reduces Hallucination

Hallucinations happen when an LLM tries to confidently guess facts it doesn't actually know. 

RAG drastically reduces hallucinations by shifting the model's task. Instead of asking:
> *"What is the company policy on remote work?" (Requires memorization)*

RAG asks:
> *"Based strictly on the following company handbook excerpt, what is the policy on remote work? If the answer is not in the text, say 'I don't know.'\n\n[Excerpt Injected Here]" (Requires reading comprehension)*

Because LLMs have phenomenal reading comprehension, grounding their answers in retrieved evidence is highly reliable.

---

## When to Use RAG

You should implement a RAG architecture when:
1. **The data is private:** The LLM was not trained on your internal company documents, customer data, or proprietary code.
2. **The data changes frequently:** News articles, stock prices, or live inventory levels change too rapidly for an LLM to be continuously retrained.
3. **Accuracy is critical:** You need the AI to cite its sources and provide factual answers rather than creative guesses.

If the answer relies purely on general world knowledge (e.g., "How does a combustion engine work?"), standard prompting is sufficient and RAG is unnecessary.

---

## Vector Databases: The Engine of RAG

If you want to inject relevant documents into the prompt, how do you find them quickly out of millions of files? You can't just use keyword search (like `CTRL+F`), because users often ask questions using synonyms. 

This is where **Vector Databases** come in.

In Week 8, you learned about **Embeddings**—taking text and converting it into a long list of numbers (a vector) that represents its semantic meaning. A Vector Database (like Pinecone, Chroma, or Qdrant) is specially designed to:
1. **Store** millions of these embeddings.
2. **Enable Similarity Search at Scale:** It rapidly calculates the mathematical distance (e.g., cosine similarity) between vectors to find texts that share similar meanings, even if they don't share the exact same words.

---

## The RAG Retrieval Pipeline

A standard RAG system operates in a distinct, multi-step pipeline every time a user asks a question:

1. **Query:** The user asks a question (e.g., *"How many vacation days do I get?"*).
2. **Embed:** Your Python code calls an embedding model to convert the user's question into a numerical vector.
3. **Similarity Search:** You send this question vector to your Vector Database.
4. **Top-K Retrieval:** The database compares the question vector against all stored document vectors and returns the "Top-K" (e.g., the top 3) most mathematically similar chunks of text.
5. **Inject into Prompt:** Your Python code takes those top 3 text chunks and pastes them into the `system` or `user` prompt.
6. **Generate:** The LLM reads the injected text and generates the final answer for the user.

---

## Example RAG Workflow (Conceptual Python)

Here is a conceptual look at how a RAG pipeline is orchestrated in Python. *(Note: We will dive deeper into writing the actual code for embeddings and vector databases in upcoming modules).*

```python
import anthropic

def simple_rag_pipeline(user_question, vector_db_client, api_key):
    # Step 2: Embed the user's question (Conceptual)
    question_vector = embed_text(user_question)
    
    # Steps 3 & 4: Similarity Search to get Top-K documents
    # The database returns the actual text of the most relevant documents
    retrieved_docs = vector_db_client.search(question_vector, top_k=3)
    
    # Step 5: Inject into Prompt
    context_string = "\n\n".join(retrieved_docs)
    
    system_prompt = f"""
    You are a helpful HR assistant. Answer the user's question based ONLY on the following context.
    If the context does not contain the answer, say "I cannot find the answer in the provided documents."
    
    <context>
    {context_string}
    </context>
    """
    
    # Step 6: Generate
    client = anthropic.Anthropic(api_key=api_key)
    response = client.messages.create(
        model="claude-3-haiku-20240307",
        max_tokens=300,
        system=system_prompt,
        messages=[{"role": "user", "content": user_question}]
    )
    
    return response.content[0].text
```

By following this pipeline, you give the LLM the exact context it needs right before it answers, completely bypassing its limitations in memory and training data.
