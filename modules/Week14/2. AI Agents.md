## What is an AI Agent?

Up until now, our AI interactions have been mostly reactive and linear: you ask a question, the AI gives an answer, and the script stops. Even in a RAG pipeline, the Python code is doing the "thinking" (searching the database) and simply handing the results to the LLM to read.

An **AI Agent** flips this dynamic. Instead of just answering questions, an Agent is given a goal, a set of tools, and the autonomy to loop through tasks, make decisions, and interact with the outside world until the goal is achieved.

### The Anatomy of an Agent
An AI Agent consists of four core components:
1. **The Brain (LLM):** The core intelligence responsible for reasoning, planning, and deciding what to do next.
2. **Memory:** The ability to remember past actions and conversation history. (Short-term memory via the `messages` array, and sometimes long-term memory via a database).
3. **Tools:** Functions that the LLM is allowed to call. This could be a calculator, a web search function, an internal API, or even a script that executes SQL queries.
4. **The Planning Loop:** A while-loop in Python that continuously prompts the LLM to look at its memory, decide on an action, use a tool, observe the result, and repeat until the task is complete.

---

## The ReAct Pattern: Reason, Act, Observe

The most common framework for building AI agents is the **ReAct** pattern (Reason + Act). 

When a user gives the Agent a complex goal, the Python loop forces the LLM to follow this strict cycle:

1. **Thought (Reason):** The LLM analyzes the goal and thinks about what it needs to do next. *(e.g., "The user wants to know Apple's stock price today and compare it to last week. First, I need to find today's date.")*
2. **Action (Act):** The LLM decides to call one of its provided tools. *(e.g., `call_tool("get_current_date")`)*
3. **Observation (Observe):** The Python script executes the tool, gets the result, and feeds it back to the LLM. *(e.g., "Today is October 15, 2024.")*
4. **Repeat:** The LLM uses that observation to form a new Thought. *(e.g., "Now I know the date. Next, I need to call the stock API for AAPL.")*

This loop continues until the LLM decides it has enough information to formulate a final answer for the user.

---

## Agent vs. Simpler Flows: The Decision Matrix

AI Agents are powerful, but they are also slow, expensive, and unpredictable. You should only use an Agent when simpler flows won't work. Use this decision matrix when designing your application:

1. **Direct Call:** Use when the task is simple and relies purely on the LLM's internal knowledge. *(e.g., "Summarize this email.")*
2. **Chained Calls:** Use when the task requires a strict, linear series of predictable steps. *(e.g., Call LLM to extract names -> Call LLM to format names as JSON -> Save to database.)*
3. **RAG (Retrieval-Augmented Generation):** Use when the LLM needs factual information from a specific database to answer the question, but the retrieval process is straightforward. *(e.g., "What is our refund policy?")*
4. **Agent:** Use when the path to the solution is unknown and requires dynamic decision-making. *(e.g., "Research our top 3 competitors, find their pricing models, and write a comparative report.")*

---

## When NOT to Use Agents

Because Agents operate autonomously inside a loop, they can easily go off track, get stuck in infinite loops, or make poor decisions. 

You should **never** deploy fully autonomous Agents for:
- **High-stakes tasks:** E.g., medical diagnoses, legal judgments, or financial trading.
- **Irreversible actions:** E.g., deleting a database, sending bulk emails to customers, or executing financial transactions.

**The Golden Rule of Agency:** For any action that modifies data or interacts with the real world (like sending an email or executing a transaction), the Agent must pause and wait for a **Human-in-the-Loop (HITL)** to approve the action before the Python script executes it.
