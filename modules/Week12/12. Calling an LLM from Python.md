# Calling an LLM from Python

---

## Why Call an LLM?

Up until now, you have been writing Python code that performs logic locally on your machine. You've learned how to organize code into **Functions**, store data in **Lists** and **Dictionaries**, save and read data with **File Handling**, and anticipate crashes with **Errors and Exceptions**. 

But the real power of modern software development comes from connecting to external systems to borrow capabilities you don't want to build yourself. Calling a Large Language Model (LLM) from Python is exactly that: your code asks another computer (owned by Anthropic, OpenAI, or Google) to do the heavy lifting of generating text, and then waits for the answer to come back. 

This unit bridges the gap between writing prompts in a web browser and executing them programmatically. Python becomes the orchestration layer that prepares the prompt (often using dictionaries and lists), makes the call, handles potential API errors with `try/except`, and processes the result.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **API** | Application Programming Interface; a set of rules that lets one software system talk to another. |
| **Request** | The message you send to the API, containing your instructions. |
| **Response** | The data the API sends back, usually containing the AI's generated text. |
| **Authentication (API Key)** | A secret password that proves you are authorized to use the service. |
| **JSON** | JavaScript Object Notation; the standard data format for APIs, which looks almost exactly like Python dictionaries and lists. |

## What is an API?

An **API (Application Programming Interface)** is a set of rules that lets one software system talk to another. If a graphical user interface (GUI) is how a human interacts with an application (like clicking buttons on a website), an API is how a program interacts with another program.

Think of an API as a waiter in a restaurant. You (the client) give your order (a **request**) to the waiter. The waiter takes it to the kitchen (the server or external system), the kitchen prepares the meal, and the waiter brings the food (the **response**) back to you.

When calling an LLM, you are sending a request over the internet to Anthropic's servers, containing your prompt and instructions. Anthropic processes it and sends back a response containing the generated text.

---

## The Anthropic API Components

To make a successful request to the Anthropic API, you need a few core components:

- **Authentication (API Key):** A secret password that tells Anthropic who to bill for the usage. Never share this key or upload it to public repositories.
- **Model:** You must specify which version of the LLM you want to use (e.g., `claude-3-5-sonnet-20240620`). 
- **System Prompt (Optional):** High-level instructions that set the AI's persona, rules, and boundaries.
- **Messages Array:** A Python list containing dictionaries of the conversation history. Each dictionary has a `"role"` (usually `"user"` or `"assistant"`) and `"content"`.
- **User Prompt:** The most recent message from the user, usually placed at the end of the messages array.

## Making the First API Call

To call the Anthropic API from Python, you first need to install Anthropic's official Python library, which handles the complex HTTP networking under the hood.

**1. Install the library (in Google Colab):**
```python
!pip install anthropic
```

**2. Write and run the call:**
```python
import os
import anthropic

# Initialize the client with your API key
client = anthropic.Anthropic(
    api_key="sk-ant-your-actual-api-key-here",
)

# Make the API call
response = client.messages.create(
    model="claude-3-5-sonnet-20240620",
    max_tokens=1000,
    system="You are a helpful coding assistant.",
    messages=[
        {"role": "user", "content": "Write a short poem about Python."}
    ]
)
```

Notice how `messages` is just a **List** of **Dictionaries** — data structures you learned earlier this week!

---

## Parsing the JSON Response

APIs communicate using standard data formats, most commonly **JSON**. JSON looks almost exactly like Python dictionaries and lists.

When Anthropic sends back the response, it contains metadata (tokens used, request ID, model). The actual text is buried inside this structure.

```python
# The text is inside the first element of the 'content' list
generated_text = response.content[0].text
print(generated_text)
```

## Handling API Errors

Over the internet, things fail. The Wi-Fi drops, the API key might be invalid, or servers might be overloaded. Just like you learned in the **Errors and Exceptions** unit, a robust program anticipates these failures using `try/except` blocks:

```python
import anthropic

try:
    response = client.messages.create(
        model="claude-3-5-sonnet-20240620",
        max_tokens=1000,
        messages=[{"role": "user", "content": "Hello!"}]
    )
    print(response.content[0].text)

except anthropic.AuthenticationError:
    print("Error: Your API key is invalid or missing.")
except anthropic.RateLimitError:
    print("Error: You are sending requests too quickly. Please slow down.")
except anthropic.APIConnectionError:
    print("Error: Could not connect to Anthropic.")
except Exception as e:
    print(f"An unexpected error occurred: {e}")
```

## Every API Call is a Design Decision

When building real-world AI applications, every call involves engineering tradeoffs:

- **Latency (Speed):** Making an API call over the network takes time.
- **Cost:** You pay per token (roughly per word) for both input and output. Sending a massive document every time drains your budget.
- **Reliability:** External systems go down. You need fallback plans or retry mechanisms.

Choosing a smaller, faster model (like Claude 3 Haiku) instead of the most powerful one (like Claude 3.5 Sonnet) is a classic design decision balancing latency, cost, and capability.

## Try it Yourself

**Problem Statement:** Write a Python function that takes a user's topic, calls the Anthropic API to generate a one-sentence fun fact about that topic, extracts only the text from the response, and handles the case where the API key is invalid.

```python
import anthropic

def get_fun_fact(topic, api_key):
    try:
        # Initialize client
        client = anthropic.Anthropic(api_key=api_key)
        
        # Make the API call
        response = client.messages.create(
            model="claude-3-haiku-20240307", # Fast, cheap model
            max_tokens=100,
            system="You are an expert at providing short, one-sentence fun facts.",
            messages=[
                {"role": "user", "content": f"Give me a fun fact about {topic}."}
            ]
        )
        
        # Parse the response
        fact = response.content[0].text
        return fact

    except anthropic.AuthenticationError:
        return "Failed: The provided API key is invalid."
    except Exception as e:
        return f"Failed: An unexpected error occurred: {e}"

# Call the function
print(get_fun_fact("space", "fake-api-key-123"))
```

Expected Output:
```
Failed: The provided API key is invalid.
```

## Common Mistakes

- **Leaking API Keys:** Hardcoding your API key and uploading the script to GitHub. Anyone can find it and rack up a massive bill on your account.
- **Assuming success:** Making API calls without `try/except` blocks. If the network drops, your entire program crashes.
- **Not parsing the response:** Printing the raw `response` object and getting a giant block of JSON metadata instead of the clean text you wanted.
- **Using the wrong model for the job:** Paying 10x more for the most advanced model just to perform a simple text classification task.

## Interview Questions

**Q1: "What is an API?"**

A: An Application Programming Interface is a set of rules that allows one software system to communicate with another, often used to request data or trigger actions on a remote server.

**Q2: "How do you handle network instability or API failures in your code?"**

A: By using `try/except` blocks to gracefully catch specific exceptions (like connection timeouts or rate limits) instead of letting the application crash.

**Q3: "What format does the Anthropic API (and most modern APIs) use to send data back?"**

A: JSON (JavaScript Object Notation), which maps cleanly to Python dictionaries and lists.

## Quick Recap

- An **API** allows your Python code to request work from external systems, like Anthropic's LLMs.
- The Anthropic API requires an **API key**, a specified **model**, and a **messages array** containing the conversation.
- You interact with the API using the `anthropic` Python package.
- The AI's response comes back as JSON data; you must **parse** it (e.g., `response.content[0].text`) to extract the actual words.

- Every API call involves tradeoffs between **latency**, **cost**, and **reliability**.
