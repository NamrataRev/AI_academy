## 3. Description

### 3.1 What an API is — a door into another system

An **API (Application Programming Interface)** is a set of rules that lets one software system talk to another. If a graphical user interface (GUI) is how a human interacts with an application (like clicking buttons on a website), an API is how a program interacts with another program.

Think of an API as a waiter in a restaurant. You (the client) give your order (a **request**) to the waiter. The waiter takes it to the kitchen (the server or external system), the kitchen prepares the meal, and the waiter brings the food (the **response**) back to you.

When calling an LLM, you are sending a request over the internet to Anthropic's servers, containing your prompt and instructions. Anthropic processes it and sends back a response containing the generated text.

### 3.2 The Anthropic API — model, messages array, system prompt, user prompt, authentication

To make a successful request to the Anthropic API, you need a few core components:

- **Authentication (API Key):** A secret password that proves you are authorized to use the service and tells Anthropic who to bill for the usage. Never share this key or upload it to public repositories like GitHub.
- **Model:** You must specify which version of the LLM you want to use (e.g., `claude-3-5-sonnet-20240620`). Different models have different capabilities, speeds, and costs.
- **System Prompt (Optional):** High-level instructions that set the AI's persona, rules, and boundaries. It tells the AI *how* to behave before it answers the user's question.
- **Messages Array:** A list of the actual conversation history. It contains objects with a `role` (usually `"user"` or `"assistant"`) and `content` (the text of the message).
- **User Prompt:** The most recent message from the user, usually placed at the end of the messages array, containing the specific task or question.

### 3.3 Making the first API call — install, write, run

To call the Anthropic API from Python, you first need to install Anthropic's official Python library, which handles the complex HTTP networking under the hood.

**1. Install the library:**
In a Google Colab cell, you run a shell command using `!`:
```python
!pip install anthropic
```

**2. Write the call:**
```python
import os
import anthropic

# Initialize the client with your API key
client = anthropic.Anthropic(
    api_key="sk-ant-your-actual-api-key-here",
)

# Make the API call
response = client.messages.create(
    model="claude-3-5-sonnet-20240620",
    max_tokens=1000,
    system="You are a helpful coding assistant.",
    messages=[
        {"role": "user", "content": "Write a short poem about Python."}
    ]
)
```

**3. Run in Colab:**
When you execute this cell, Python pauses, sends the data across the internet to Anthropic, waits for the AI to generate the poem, and stores the final result in the `response` variable.

### 3.4 Parsing the JSON response

APIs communicate using standard data formats, most commonly **JSON (JavaScript Object Notation)**. JSON looks almost exactly like Python dictionaries and lists.

When Anthropic sends back the response, it contains a lot of metadata (how many tokens were used, the ID of the request, the model used, etc.). The actual text the AI generated is buried inside this structure.

If you print the raw `response` object, it looks like a complex data structure. To extract just the text:

```python
# The text is inside the first element of the 'content' list
generated_text = response.content[0].text
print(generated_text)
```

### 3.5 Handling API errors

Over the internet, things fail. The Wi-Fi drops, the API key might be invalid, or Anthropic's servers might be overloaded. A robust program anticipates these failures rather than crashing entirely.

Python uses `try` and `except` blocks to handle errors gracefully:

```python
import anthropic

try:
    response = client.messages.create(
        model="claude-3-5-sonnet-20240620",
        max_tokens=1000,
        messages=[{"role": "user", "content": "Hello!"}]
    )
    print(response.content[0].text)

except anthropic.AuthenticationError:
    print("Error: Your API key is invalid or missing.")
except anthropic.RateLimitError:
    print("Error: You are sending requests too quickly. Please slow down.")
except anthropic.APIConnectionError:
    print("Error: Could not connect to Anthropic. Check your internet connection.")
except Exception as e:
    print(f"An unexpected error occurred: {e}")
```

### 3.6 Every API call is a design decision

Calling an API is not free. When building real-world AI applications, every call you orchestrate involves engineering tradeoffs:

- **Latency (Speed):** Making an API call over the network takes time (often several seconds for an LLM to generate a long response). If a user is waiting for a page to load, this delay can feel like an eternity.
- **Cost:** You pay per token (roughly per word) for both the input you send and the output you receive. Sending a massive 100-page document in the prompt every single time you ask a simple question will quickly drain your budget.
- **Reliability:** External systems go down. If your entire application crashes when the Anthropic API is temporarily unavailable, your architecture is brittle. You need fallback plans or retry mechanisms.

Choosing a smaller, faster model (like Claude 3 Haiku) instead of the most powerful one (like Claude 3.5 Sonnet) is a classic design decision balancing latency, cost, and reasoning capability.

## 4. Real-World Application

Calling an LLM programmatically is the foundation of all modern AI applications:

- **Customer Support Bots:** A Python backend receives a user's message from a chat widget, formats it into an API request with a system prompt ("You are a polite support agent"), calls the Anthropic API, and sends the response back to the user.
- **Automated Data Extraction:** A script reads hundreds of PDF invoices, calls an LLM API to extract the total amount and date from each one, parses the JSON response, and saves the structured data to a database.
- **Code Assistants:** Tools like GitHub Copilot or Cursor take the code you are currently typing, package it into an API call behind the scenes, and return the suggested completion.

## 5. Worked Example

### Problem Statement

Write a Python script that takes a user's topic, calls the Anthropic API to generate a one-sentence fun fact about that topic, extracts only the text from the response, and handles the case where the API key is invalid.

### Step 1: Understand the Problem

We need to import the library, set up a client, construct the `messages.create` call with a specific prompt, parse the `content[0].text`, and wrap the whole thing in a `try/except` block to catch authentication errors.

### Step 2: Write the Python Code

```python
import anthropic

def get_fun_fact(topic, api_key):
    try:
        # Initialize client
        client = anthropic.Anthropic(api_key=api_key)
        
        # Make the API call
        response = client.messages.create(
            model="claude-3-haiku-20240307", # Use a fast, cheap model for simple tasks
            max_tokens=100,
            system="You are an expert at providing short, one-sentence fun facts.",
            messages=[
                {"role": "user", "content": f"Give me a fun fact about {topic}."}
            ]
        )
        
        # Parse the response
        fact = response.content[0].text
        return fact

    except anthropic.AuthenticationError:
        return "Failed: The provided API key is invalid."
    except Exception as e:
        return f"Failed: An unexpected error occurred: {e}"

# Call the function
print(get_fun_fact("space", "fake-api-key-123"))
```

### Step 3: Expected Output

```
Failed: The provided API key is invalid.
```

*(If a real API key were provided, the output would be a one-sentence fun fact about space, like: "Space is completely silent because there is no air or atmosphere for sound to travel through.")*

## 6. Key Takeaways

- An **API** allows your Python code to request work from external systems, like Anthropic's LLMs.
- The Anthropic API requires an **API key**, a specified **model**, and a **messages array** containing the conversation.
- You interact with the API using the `anthropic` Python package.
- The AI's response comes back as structured data; you must **parse** it (e.g., `response.content[0].text`) to extract the actual words.
- Network calls fail. Use **try/except** blocks to catch errors like `AuthenticationError` or `RateLimitError`.
- Every API call involves tradeoffs between **latency**, **cost**, and **reliability**.
